# استعادة كلمة المرور

الواجهة المرتبطة في Sites تعرض «نسيت كلمة المرور» تحت تسجيل الدخول. يرسل المستخدم بريده، ثم يفتح الرابط الذي يصله ويكتب كلمة المرور الجديدة وتأكيدها بنفسه. لا يُستخدم المسار لإنشاء حساب ولا يتيح معرفة كلمة المرور القديمة.

## إعداد البريد

الخدمة المستخدمة: Mostaofi P0 Preview في بيئة production، مشروع Mostaofi V1. تُضبط المتغيرات التالية في Variables على Railway، ثم يعاد نشر خدمة API:

| المتغير | القيمة المطلوبة |
| --- | --- |
| `MOSTAOFI_RECOVERY_ORIGIN` | أصل HTTPS لواجهة مستوفي، مثل `https://mostaofi-preview.taregali879.chatgpt.site`؛ دون مسار أو query أو fragment |
| `MOSTAOFI_MAIL_FROM` | عنوان إرسال موثّق لدى مزود البريد |
| `MOSTAOFI_SMTP_HOST` | خادم SMTP للمزود |
| `MOSTAOFI_SMTP_PORT` | 465 مع TLS مباشر، أو 587 مع STARTTLS إلزامي |
| `MOSTAOFI_SMTP_USER` | اسم مستخدم SMTP |
| `MOSTAOFI_SMTP_PASSWORD` | سر SMTP، يُدخل في Variables ولا يُرسل في المحادثة أو يضاف إلى Git |

تستخدم الخدمة `JWT_REFRESH_SECRET` القوي الموجود لتشفير طابور البريد مع فصل سياق المفتاح. يُرفض تكوين بريد غير كامل أو منفذ غير مدعوم أو اتصال دون HTTPS في رابط الواجهة. شهادة SMTP تُتحقق؛ لا يوجد تعطيل للتحقق أو سجل محتوى SMTP. توفر الإعدادات ليس إثباتًا لتسليم رسالة إلى صندوق البريد؛ يجب اختبار الوصول مع المزود.

## المسارات

| API | النتيجة |
| --- | --- |
| GET `/api/v1/auth/recovery/status` | توفر إعداد الخدمة ومدة 15 دقيقة |
| POST `/api/v1/auth/forgot-password` | `{email}`؛ رد موحد `{accepted:true}` مع إدراج مهمة مشفرة للبريد المعروف وغير المعروف |
| POST `/api/v1/auth/recovery-token` | `{token}`؛ تحقق من رمز غير مستخدم وغير منتهٍ |
| POST `/api/v1/auth/reset-password` | `{token,password,confirmPassword}`؛ تغيير كلمة المرور وإبطال الجلسات والروابط السابقة داخل transaction |

الوكيل في Sites يتيح هذه العمليات قبل جلسة الدخول، يتحقق من Origin ويقيد الحقول، ويعيد فقط نتائج النجاح المنطقية أو رموز الخطأ المعروفة. الرموز لا توضع في URL لطلبات API أو في سجلاتها. يصل رابط البريد بصيغة `/#reset=...`، ثم يمسح الجزء السري من العنوان ويحفظه في ذاكرة الصفحة. لا توجد جلسة دخول آلية بعد إعادة التعيين.

## سلامة المعاملة

الرمز عشوائي بطول 256 bit، وقاعدة البيانات تحتفظ ببصمته فقط. أي رمز موجود في مهمة بريد غير منتهية يُشفّر بـAES-GCM، ويُمسح payload بعد قبول SMTP أو نهاية المحاولات/الصلاحية. الطابور دائم، مع lease و`FOR UPDATE SKIP LOCKED` للمستهلكين المتعددين وثلاث محاولات. تُرسل الرسائل إلى بريد حساب موجود فقط؛ تُحذف مهمة البريد غير المسجّل دون إرسال.

الحدود موزعة في PostgreSQL: ثلاث طلبات للبريد و30 للعنوان خلال 15 دقيقة، وعشر محاولات إعادة تعيين خلال 15 دقيقة. يُقبل عنوان العميل الممرر من Sites فقط عند مطابقة مفتاح الخادم المشترك؛ خلاف ذلك يُستخدم عنوان المتصل الفعلي. لا يقبل المسار جهة إعادة توجيه من طلب المستخدم.

تغيير كلمة المرور يستهلك الرمز بمعاملة واحدة مع قفل المستخدم، يزيد نسخة بيانات الاعتماد، ويُبطل جلسات التجديد وكل الروابط السابقة، ويسجل Audit لكل عضوية، ويضيف إشعار تغيير للبريد. يفحص JWT Guard نسخة الاعتماد في قاعدة البيانات، بما فيها access tokens السابقة. يبقى JWT قديم بدون نسخة صالحًا للمستخدم ذي النسخة 0 فقط. تُمنع كذلك مهام طلب الاستعادة الأقدم من آخر تغيير للبيانات من إصدار روابط متأخرة.

المهاجرة إضافية: أعمدة credential version/timestamp في users، وجداول طلبات الاستعادة وطابور البريد وحدود المحاولات. تُطبق قبل تشغيل النسخة الجديدة. لا تتغير كلمة مرور أي مستخدم عند النشر. الرجوع إلى خادم قديم لا يزيل المهاجرة، لكنه يزيل فرض إبطال access tokens بنسخة الاعتماد؛ لذلك لا يرجع مشغل المنصة إلى Guard قديم بعد استخدام الاستعادة إلا مع خطة جلسات مدروسة.

## التحقق المتبقي

اختبارات الخدمة تشمل انتهاء الرمز واستهلاكه وتعارضه، التجزئة والأدوار وإبطال JWT، عدم كشف الحساب، تشفير الطابور، وتكوين TLS. تُختبر SQL للمهاجرة وحدود المحاولات وlease في PostgreSQL مضمّن. يوجد اختبار mock للإرسال؛ لا يمثل إثبات وصول رسالة حقيقية. التشغيل الكامل يحتاج إعداد SMTP واختبار بريد حساب مملوك وتغيير كلمة المرور والدخول من جلسة جديدة. لا تسجل الرموز أو كلمات المرور ضمن أدلة الاختبار.
